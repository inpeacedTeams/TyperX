# TyperX · AI Studio

**Твой голос. Живой ритм.**

Windows-приложение: Telegram → OpenAI-совместимая модель → SmartSplitter → TypingService → драйвер Interception. Новый интерфейс работает на HTML/CSS/JS внутри Qt WebEngine. Прямой отправки сообщений через Telegram API нет.

## Установка и запуск

Windows 10/11, Python 3.12, установленный Interception (запусти `install_driver.bat` от администратора и перезагрузи Windows).

```powershell
git clone https://github.com/inpeacedTeams/TyperX.git
cd TyperX
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -e ".[dev]"
python -m typerx
```

Старый редактор, шаблоны, Monkeytype и F10 сохранены: `python -m typerx --legacy`. Старый `state.json` не удаляется.

## Выбор таргета по сообщению

1. **Telegram:** введи `api_id` / `api_hash` с `my.telegram.org`, номер телефона, код и при необходимости пароль 2FA.
2. Нажми **Загрузить чаты**, выбери чат. Показывается текст из его последних 50 сообщений с именами авторов.
3. **Нажми на сообщение нужного человека.** Его Telegram ID становится таргетом в текущем чате. Все показанные сообщения этого автора подсвечиваются. Имена могут совпадать — фильтрация работает по ID.
4. Переключатель **Только таргет** фильтрует отображаемую историю. Он не влияет на фильтрацию модели: модель всегда получает только сообщения выбранного автора, даже когда на экране видны все участники.
5. Другой автор выбирается кликом на его сообщение. **Сбросить** убирает таргета. Переключение чата тоже сбрасывает выбор и подготовленный запуск.

Поддерживаются личные чаты и обычные группы, включая супергруппы без форум-топиков. Каналы, форум-топики, свои сообщения, боты, удалённые и анонимные авторы не используются как таргеты. В группе ответы печатаются **в той же группе**, а не в личном диалоге автора. Проверка фактической возможности ввода остаётся на GUI-защите.

**Контекст LLM:** из последних 50 сообщений чата отбираются только сообщения выбранного Telegram ID. Сообщения остальных людей и собственные исходящие сообщения не передаются. Новые сообщения другого автора или того же автора в другом чате не запускают генерацию. Просмотр истории в UI сам по себе ничего не отправляет LLM.

## Модель, личности и запуск цикла

- В разделе **Нейросеть** задай base URL (например, `https://api.openai.com/v1`), API-ключ и модель. Проверка подключения отправляет только тестовую фразу, без переписки. HTTPS обязателен, кроме localhost/127.0.0.1/::1.
- В разделе **Личности** создай пресеты. Несколько системных промптов одного набора отправляются в указанном порядке; активный набор выбирается на главном экране.
- Настрой WPM и приблизительное число слов в сообщении, подтверди передачу контекста указанному провайдеру, нажми **Подготовить запуск**.
- Поставь курсор в пустое поле нужного чата Telegram Desktop и нажми **F8**. Цикл отвечает только на новые входящие текстовые сообщения таргета, не на старую историю.
- **F9** отменяет ожидание, генерацию и печать. После остановки проверь и очисти возможный незавершённый черновик. Для смены таргета, модели или пресета сначала останови цикл.

Ручной режим на новом экране работает без Telegram и LLM.

## Анимации и интерфейс

Переходы экранов, световой блик на кнопках, орбитальный индикатор, подсветка этапов AI-цикла, анимированная волна ожидания, таймер генерации/печати, состояния загрузки и интерактивные карточки авторов. Движение можно выключить кнопкой **Анимации**; системная настройка `prefers-reduced-motion` имеет приоритет. Анимации не меняют работу движка и не создают фиктивные события.

Референсы найдены через 21st MCP: [Loading State](https://21st.dev/@theshanelevine/components/loading-state), [Shimmer Button](https://21st.dev/@Shatlyk1011/components/shimmer-button), [Dot Loader Motion](https://21st.dev/@tailwind-admin/components/dot-loader-motion). Реализация написана самостоятельно на обычных CSS/JS, без платного кода каталога, React, CDN и новых npm-зависимостей.

## Защита и ограничения

AI-режим проверяет `Telegram.exe`, HWND, заголовок окна и идентификатор поля Edit через Windows UI Automation. **Общий заголовок «Telegram» не допускается.** Нужен точный заголовок выбранного чата (для группы — название группы), возможно с суффиксом ` - Telegram`, ` – Telegram`, ` — Telegram` или ` - Telegram Desktop`, и уникальное название среди загруженных чатов. Если версия Telegram не предоставляет нужный заголовок/UIA-поле, AI-режим с ней пока несовместим.

Это консервативная GUI-проверка, не гарантированная привязка интерфейса к peer ID. Не меняй чат/поле и не вводи текст вручную во время работы. Смена окна, заголовка, поля, потеря соединения и ошибки останавливают цикл; автоматической повторной отправки нет.

Модель должна поддерживать `/chat/completions` и текстовый `message.content`; Поддерживается SSE streaming и обычный JSON-ответ; tool calls не поддерживаются. Ответ собирается полностью до печати; оборванный или обрезанный ответ не печатается. Каждый текст истории ограничен 6000 символами, ответ — 8000. Медиа без текста не запускает ответ. Неподдерживаемые драйвером символы, включая emoji, останавливают ответ до начала печати; clipboard и Unicode SendInput fallback не используются. Старый автоответ «123» в AI-режиме отключён. После F9 сервер может закончить уже принятый LLM-запрос, но его результат не попадёт в печать.

## Локальные данные

В `%APPDATA%\TyperX`: `ai.json` — настройки и пресеты; `ai-secrets.bin` — ключ LLM и Telegram API hash под Windows DPAPI; `telegram.session` — чувствительная Telethon SQLite-сессия, **не зашифрованная DPAPI**. Не публикуй её и не включай в облачные бэкапы. Код входа и пароль 2FA не сохраняются. Выход из Telegram отзывает сессию и удаляет её файл; ключи можно изменить, ключ LLM — удалить флажком.

История и ответы не записываются в журнал на диске. Веб-интерфейс не имеет сетевого доступа; чужой текст отображается через `textContent`. LLM-перенаправления запрещены. DPAPI не защищает от программ, работающих от имени того же пользователя Windows. Используй автоответы с согласия собеседника.

## Проверки и сборка

```powershell
ruff check src tests
python -m pytest
python -m compileall -q src
pyinstaller --clean --noconfirm typerx.spec
```

EXE: `dist\TyperX.exe`. В сборку включены WebEngine, локальные веб-ресурсы и Telethon. Windows CI отдельно проверяет настоящий WebView/QWebChannel; это не проверка Telegram или реального драйверного ввода.

Автономные регрессионные тесты:

```powershell
$env:PYTHONPATH="src"
python -m unittest discover -s tests -p "test_ai*.py" -v
```

Обязательная ручная проверка на Windows перед использованием: вход/2FA, выбор автора из личного чата и группы, фильтрация чужих сообщений, реальная печать, F9 во время генерации и печати, смена окна/чата/поля, неподдерживаемый символ и потеря сети. Офлайн-тесты её не заменяют.

## Архитектура

`domain` — splitter/ритм; `services` — набор; `platform` — Win32/Interception; `ai.py` — хранилище/LLM/Telegram/ReplyLoop; `ai_runtime.py` — отмена и защита ввода; `targeting.py` — привязка автора к чату и фильтрация контекста; `ui/web_window.py` — ограниченный QWebChannel; `ui/web` — интерфейс. Legacy UI сохранён отдельно.

## F8/F9 и перенос LLM-потока из flashReply

В AI Studio F8/F9 теперь опрашиваются в отдельном потоке через GetAsyncKeyState, без конфликта RegisterHotKey с другими приложениями и без ожидания очереди Qt. Удержание F8 не повторяет запуск, F9 имеет приоритет. Клавиши не перехватываются эксклюзивно: другое приложение тоже может на них отреагировать. Не запускай одновременно несколько экземпляров TyperX.

После F8 в событиях появляется «F8 получен», затем «Ожидание нового сообщения» либо причина отказа. Сначала выбери таргета и нажми «Подготовить запуск», затем поставь курсор в пустое поле выбранного Telegram-чата и нажми F8. Запуск не отвечает автоматически на старые 50 сообщений. Если события о F8 нет, проверь Fn/Fn Lock и что обновлён именно запущенный EXE. Общий заголовок Telegram по-прежнему отклоняется: защита чата не ослаблена.

Из исходников предоставленного flashReply адаптированы SSE-чтение, отдельные системные сообщения, temperature 0.75 / max_tokens 600 и новый анонимный x-agent-session для каждой генерации. Поддерживаются адрес сервера, base URL с /v1 и полный /chat/completions. Сохранены HTTPS-проверки и безопасные HTTP-ошибки. Файлы config.json, Telegram-сессии, Git-история и отправка через Telegram API из архива не переносились.

Офлайн-тесты проверяют события F8/F9 и SSE, но физические горячие клавиши и реальная драйверная печать требуют проверки на Windows.
