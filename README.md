# TyperX

**Твой голос. Живой ритм.**

TyperX — Windows-приложение для естественного набора текста через драйвер Interception. AI Studio связывает Telegram, OpenAI-совместимую модель и существующий движок печати. Интерфейс на HTML/CSS/JS работает в нативном окне Qt WebEngine; Qt-виджеты не используются для содержимого нового интерфейса.

## Возможности

- Telegram: вход по номеру, коду и 2FA; локальная сессия; список чатов и текст из последних 50 сообщений.
- LLM: base URL, ключ, модель и проверка подключения без передачи переписки.
- Наборы личностей: несколько системных промптов одновременно, сохранение пресетов и переключение в один клик.
- Последовательный цикл: новое входящее сообщение → история → модель → SmartSplitter → TypingService → Interception.
- Настраиваемые WPM и приблизительное число слов в сообщении, человеческий ритм и паузы существующего движка.
- Индикация получения сообщения, генерации, печати, ожидания и ошибок.
- F8 запускает подготовленный режим; F9 отменяет цикл. Никаких автоматических повторных отправок после ошибки.
- Новый ручной режим без Telegram/LLM. Старый редактор, шаблоны, F10 и Monkeytype сохранены в `--legacy`.

## Установка

Windows 10/11, Python 3.12 и установленный драйвер Interception.

```powershell
git clone https://github.com/inpeacedTeams/TyperX.git
cd TyperX
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -e ".[dev]"
# install_driver.bat — запуск от администратора, затем перезагрузка
python -m typerx
```

## Первый запуск AI-режима

1. В разделе **Telegram** введи свои `api_id` и `api_hash` из API development tools на `my.telegram.org`, затем номер телефона. Запроси код; при необходимости введи пароль 2FA. Код и пароль 2FA не сохраняются.
2. Нажми **Загрузить чаты**, выбери собеседника и проверь историю. История доступна для любого чата; автоответ включается только для личного чата с человеком, не группы, канала, бота или «Избранного».
3. В разделе **Нейросеть** задай base URL (например, `https://api.openai.com/v1`), API-ключ и модель. Нажми **Проверить подключение**. Для локального сервера разрешён HTTP только на localhost/127.0.0.1/::1.
4. Настрой **Личности**. Промпты выбранного набора объединяются в указанном порядке. На главном экране выбери активный набор, скорость и длину сообщений.
5. Подтверди передачу контекста выбранному LLM-провайдеру и нажми **Подготовить запуск**.
6. Открой нужный чат в Telegram Desktop, поставь курсор в пустое поле сообщения и нажми **F8**. Первым поводом для ответа станет новое входящее текстовое сообщение, а не старая история.
7. **F9** останавливает режим. После остановки проверь и очисти возможный незавершённый черновик, затем подготовь запуск заново.

### Важная защита выбранного чата

Драйвер печатает в GUI, а не отправляет сообщения по Telegram peer ID. Поэтому одного HWND недостаточно. AI Studio проверяет процесс `Telegram.exe`, заголовок окна, выбранного собеседника и идентификатор поля ввода через Windows UI Automation.

**AI-режим намеренно отказывается запускаться в окне с общим заголовком «Telegram».** Нужен заголовок с точным именем выбранного собеседника (допустим суффикс ` - Telegram`, ` – Telegram`, ` — Telegram` или ` - Telegram Desktop`), пустое доступное UIA-поле Edit и уникальное имя среди загруженных чатов. Используй отдельное окно чата, если твоя версия Telegram поддерживает такой заголовок. Если версия Telegram не предоставляет нужные заголовок/UIA-данные, этот AI-режим с ней пока несовместим: не отключай проверку ради запуска.

Смена окна, заголовка, фокуса поля, потеря соединения и ошибки останавливают весь цикл, включая ожидание модели. Это консервативная GUI-проверка, не гарантированная привязка GUI к peer ID. Не переключай чаты и не вводи текст вручную во время работы. Переключение личности/таргета/настроек требует F9.

## Локальные данные и приватность

Данные лежат в `%APPDATA%\TyperX`:

- `ai.json` — настройки и пресеты; секретных ключей нет;
- `ai-secrets.bin` — API-ключ LLM и Telegram API hash, защищённые Windows DPAPI текущего пользователя;
- `telegram.session` — локальная Telethon-сессия. Это чувствительный SQLite-файл авторизации, **не зашифрованный DPAPI**. Не отправляй его другим и не включай в облачные резервные копии;
- старый `state.json` не мигрируется и не удаляется; он продолжает использоваться в `--legacy`.

При генерации до 50 сообщений выбранного чата передаются на настроенный base URL. Система не сохраняет историю или ответы LLM в журнал на диске. Веб-интерфейс не имеет сетевого доступа: HTTP-запросы выполняются Python-адаптером. Чужой текст отображается через `textContent`, не через HTML. HTTP-перенаправления LLM запрещены, чтобы не передать ключ другому серверу.

Выход из Telegram в приложении отзывает эту сессию и удаляет её локальный файл. Ключи не удаляются при выходе: их можно изменить; ключ LLM можно удалить отдельным флажком. DPAPI не защищает от программ, работающих от имени того же пользователя Windows.

## Ограничения

- Требуется OpenAI-совместимый `/chat/completions` с текстовым `message.content`; streaming и tool calls не поддерживаются.
- Контекст ограничен 50 последними сообщениями, текст каждого — 6000 символами, ответ — 8000. Медиа без текста не вызывает ответ.
- Для драйверной печати нужны доступные раскладки. Emoji и другие неподдерживаемые символы приводят к остановке **до начала печати ответа**; Unicode SendInput и clipboard-fallback не используются.
- Сервер LLM может закончить уже полученный запрос после F9, но результат отменённого запроса не отправляется в печать.
- В AI-режиме отключён старый автоответ «123», чтобы исключить второй независимый источник отправок.
- Старые расширенные функции доступны через `python -m typerx --legacy`, а не в новом интерфейсе.

## Проверка и сборка

```powershell
ruff check src tests
python -m pytest
python -m compileall -q src
pyinstaller --clean --noconfirm typerx.spec
```

EXE: `dist\TyperX.exe`. В сборку включены Qt WebEngine, локальные HTML/CSS/JS и Telethon. GitHub Actions запускает тесты и сборку на Windows.

Автономные тесты нового AI-ядра можно запустить без Qt/Telegram/драйвера:

```powershell
$env:PYTHONPATH="src"
python -m unittest discover -s tests -p test_ai.py -v
```

Перед реальным использованием обязателен ручной smoke-test на Windows: вход/2FA, выбранный чат, пустое поле, запрос модели, реальная печать, F9 во время генерации и печати, смена окна/чата/поля, неподдерживаемый символ и потеря сети. Офлайн-тесты не заменяют эту проверку. Не считай AI-ответы безошибочными и используй автоматические ответы с согласия собеседника.

## Архитектура

`domain` — модели, splitter и ритм; `services` — существующий движок набора; `platform` — Interception/Win32; `persistence` — старое локальное хранилище; `ai.py` — AIStore, LLM, read-only Telegram и ReplyLoop; `ai_runtime.py` — отмена, UIA/focus guard и оркестрация; `ui/web_window.py` — ограниченный QWebChannel-мост; `ui/web` — новый интерфейс. Старый UI сохранён как legacy.
